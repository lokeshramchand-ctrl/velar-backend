# File: `routers/v1.py`

## Purpose
The core transaction-intelligence router: categorization (broken), merchant resolution (working), and confidence evaluation (working).

## Responsibilities
- Expose `POST /v1/categorize`, `POST /v1/resolve`, `POST /v1/confidence/evaluate`.
- Translate HTTP requests into calls against `engines/` and `services/`.
- Persist categorized transactions to MongoDB (intended, currently broken).

## Imports
| Import | Used for |

| `re` (imported twice, redundantly) | Regex extraction of an amount from raw text |

## Exports
**`router`** — the `APIRouter` instance, imported by `app.py` and mounted with `dependencies=[Depends(validate_api_key)]`.

## Execution Flow
1. On import, `router = APIRouter(prefix="/v1", tags=["Transaction Intelligence"])` is created, and the three route handlers plus two local Pydantic models (`ResolveRequest`, `MockModelPrediction`) are declared.
2. Per-request: FastAPI matches the path/method, runs the auth dependency (attached at `app.py`'s `include_router` call, not visible in this file), validates the request body against the declared Pydantic model, then invokes the matching handler function.

## Functions (plain English)

### `categorize_transaction(request: CategorizeRequest)`
Bound to `POST /v1/categorize`. In simple English: "Take the submitted text, run it through the rule engine to guess a merchant and category, then try to pull out a rupee amount from the text using a regex, and save all of this to the database." **In practice this crashes**: it calls `request.get("text", "")`, but `request` is a Pydantic model instance, not a dictionary, and Pydantic models don't have a `.get()` method — this raises `AttributeError` before the function can finish. Even setting that aside, the code that builds the MongoDB document assigns `"merchant": merchant_resolver` (the resolver *object itself*, not a resolved merchant name), `"category": categorize_transaction` (this very function, referencing itself), and `"confidence": confidence_engine` (the confidence engine object) — these are clearly leftover placeholder values the original author meant to replace (the code comments literally say `# CHANGE THIS to...`) and never did. It also calls `time.timezone.utc`, but `time.timezone` is a plain integer constant (seconds offset from UTC) in the `time` module, not an object with a `.utc` attribute — accessing `.utc` on an int raises `AttributeError: 'int' object has no attribute 'utc'`, a second, independent bug that would also fire if execution ever reached that line. (The intended call was almost certainly `datetime.now(timezone.utc)`, using the `timezone` class from the `datetime` module — which is already imported in this file — not the unrelated `time` module.)

### `resolve_transaction_merchant(request: ResolveRequest)`
Bound to `POST /v1/resolve`. In simple English: "Take the submitted raw bank/UPI text and hand it to the merchant resolver, then send back whatever it figures out." This is a clean, working, one-line delegation with no bugs.

### `evaluate_prediction_confidence(request: MockModelPrediction)`
Bound to `POST /v1/confidence/evaluate`. In simple English: "Take a category prediction and its confidence score, run it through the confidence wall, and send back the verdict (trusted as-is, or overridden to Unknown)." Also a clean, working, one-line delegation.

## Classes

### `ResolveRequest(BaseModel)`
One field: `text: str`. The request body shape for `/v1/resolve`.

### `MockModelPrediction(BaseModel)`
Two fields: `predicted_category: str`, `raw_confidence: float`. The request body shape for `/v1/confidence/evaluate`. The name "Mock" signals this stands in for what would eventually be a real upstream ML model's output.

## Interfaces
The three Pydantic models (`CategorizeRequest` from `models/schemas.py`, plus the two local ones) function as the request-shape contracts FastAPI validates incoming JSON against automatically.

## Hooks
The auth dependency (`Depends(validate_api_key)`) is attached externally at `app.py`'s `include_router(v1.router, dependencies=[...])` call — it is not visible anywhere in this file itself, but it runs before every handler here.

## Utilities
None — no standalone helper functions; all logic lives directly in the three route handlers.

## Dependencies
`fastapi`, `pydantic`, `re`, `time`, `datetime` (third-party/stdlib); `models.schemas`, `engines.rule_engine`, `engines.confidence_engine`, `services.merchant_resolver`, `database.mongo` (internal).

## Side Effects
- `categorize_transaction` (when/if it worked) would write a new document to `db.transactions` — a real, persistent side effect.
- `resolve_transaction_merchant` triggers real MongoDB read queries (via `merchant_resolver.resolve`) — read-only, no writes.
- `evaluate_prediction_confidence` has zero I/O side effects — pure in-memory computation.

## Performance Considerations
- `rule_engine.categorize` is fast (pre-compiled regex, in-memory dict lookup) — negligible per-request cost.
- `merchant_resolver.resolve` can issue up to one Mongo query per word (≥4 characters) in the cleaned text if no exact match is found — a potential per-request cost that scales with input text length and lack of match, on an unindexed field.
- `confidence_engine.evaluate` is pure in-memory computation — negligible cost.
- The unused `import re` (appearing twice) and unused `from fastapi import requests` are harmless dead imports with no runtime performance cost, just a minor code-cleanliness issue.
